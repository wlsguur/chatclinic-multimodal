03The plugin contract

tool.json (manifest)

"name": "gi_lesion_detector",
"entrypoint": "plugins.gi_lesion_detector.logic:execute",
"task": "gi_lesion_detection",
"modality": "medical-image",
"approval_required": false,
"source_types": ["image"],
"initial_for": [],          // on-demand
"direct_chat": {
   "requested_view": "detection_review",
   "studio": {"renderer": "detection_review"}
}

logic.py → execute(payload)→dict

def execute(payload: dict) -> dict:
    image_path = payload["image_path"]
    # lazy-load model, run inference
    return {
      "tool", "task", "summary",
      "draft_answer",
      "detections": [{box, score, label}],
      "artifacts": {"detection_review": {...}},
      "studio_cards": [...],
      "provenance": {model, device, runtime},
      "used_tools": [...] }
Same shape as built-in tools (image/nifti review) → the runner serializes it and the response layer carries artifacts + studio_cards straight to the UI.

06How a tool actually runs (backend)

Discovery & invocation

  • discover_tools() scans every plugins/*/tool.json at startup
  • run_tool(name, payload) reads entrypoint → load_plugin_execute("module:function") → calls execute(payload)
  • payload = { "image_path": <uploaded source path> } (+ optional knobs)
  • Fallback: if no entrypoint, a run.py --input/--output subprocess

Selection & approval

  • Deterministic: initial_for tools auto-run on upload (intake review)
  • On-demand: our detectors fire via @alias in chat (frontend maps alias → /api/v1/tools/{tool}/run)
  • LLM: grounded chat ($studio …) uses OpenAI gpt-5-mini over the Studio state
  • approval_required is surfaced in the tool registry for the UI to gate the CT tool
Policy lives in the Skill; invocation lives in the runtime. The two are kept separate by design.

07Orchestration — the Skill routing

Added to skills/chatgenome-orchestrator/SKILL.md. Resolve top-to-bottom; stop at first match.

The 5-step decision

  1. Source family — DICOM/NIfTI CT → lung_nodule_ct; raster → step 2
  2. Region (image_review hint) — chest X-ray → lung_nodule_cxr; colonoscopy → step 3
  3. Clinical context — still/accuracy → gi_lesion; video/real-time → polyp
  4. Host/runtime — CT needs GPU+approval; 2D tools CPU-friendly
  5. Approval — only CT; all outputs are decision-support, never a diagnosis

Why it scores

  • Same colonoscopy frame → choice depends on context (accuracy vs latency), not source type
  • Explicit ordering (image_review → detector) & dependency
  • Approval rule is cost-based and justified
  • Each tool yields a complementary artifact, not a duplicate
Multi-tool + a routing policy > a single isolated tool — the rubric's bonus criterion.

08Frontend — the detection_review renderer

From tool result to UI

  • runDetectionTool() maps aliases (lung_nodule_ct/cxr, polyp, gi_lesion) → the tool, filtered by source type
  • Merges result.artifacts.detection_review + provenance into the active analysis
  • Activates the detection_review Studio view

The card

  • 2D (image): red bounding-box overlay on the preview, label + confidence %
  • 3D (CT/NIfTI): voxel-box table (no 2D overlay)
  • Model / runtime / device line + "decision-support, not a diagnosis" footer

Registry

10Weights & deployment

Weights policy

  • CT / CXR / polyp — public pretrained, fetched by plugins/<tool>/download_weights.sh (git-ignored; two exceed GitHub's 100 MB limit)
  • gi_lesion — our fine-tuned best.pt (19 MB) committed in-repo (no public source)

Run

  • One shared Python env runs all plugins (MONAI · Ultralytics · SimpleITK · torch)
  • Backend uvicorn app.main:app :8001 · Frontend npm run dev :3000
  • GPU auto-selected (cuda:0 if available)
Blackwell host: these GPUs (sm_120) need torch ≥ 2.7 + CUDA 12.8 — reinstall torch from the cu128 index after creating the env.

11Takeaways

What was built

  • 4 detection plugins in the platform's exact contract (execute + manifest + Studio card)
  • 3 ready public models + 1 in-domain fine-tuned model
  • An explicit, auditable routing policy in the Skill
  • All GPU-verified; integrated, committed, pushed to team-detection

The lesson

Agentic AI is system design, not one model: combine ready models with a fine-tuned one, and wire them with selection logic that reasons over source → anatomy → context → runtime → approval.
